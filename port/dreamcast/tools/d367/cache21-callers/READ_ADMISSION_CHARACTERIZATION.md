sources, extracted methods, fixture changes, commands and outputs. Raw output

Actual EvtReadSub/Mram, SetRead/table, cDataCtrl setData/getNewUnit and data-unit
command/wait/clear/delete bodies execute. The controller binding name alone is
adapted to the projected Host64 Controller. FileExistCheck supplies synthetic

asset or target allocator is loaded. This is source characterization, not a
runtime repair or guest/physical-console result.

   active after failed SetRead, without any transport or backing allocation.
   The thirty-third actual getNewUnit refuses. This synthetic exhaustion proves
   the missing source cleanup; it does not show that gameplay encountered32

2. Actual setClear preserves bit1 and size; actual setDelete clears bit1/size
   and the next actual getNewUnit reuses that slot. The fixture does not decide
   whether ordinary per-room descriptor retention is intentional.
3. A deliberately seeded prior swapped1/em1 read is accepted into em0 synthetic
   promotion; the real caller overwrites metadata to0/0 without reverse/Pop.
4. Missing and undersized module boundaries each receive Push, delete the prior
   registration, and returnfailure without Pop; descriptor/data stay exact.
5. A controlled void MemorySwap refusal leaves synthetic bytes unchanged but
   the actual caller returns success/output and sets swapped1.

These controls are independent of the previously sealed allocation retry and
last-registration repair. A first capacity preflight can prevent the initial
full-table leak before DC.setData, but cannot certify a callback-changed table
after file/diagnostic work. Deleting a stale descriptor after failed SetRead is
not an acceptable substitute for a true acquisition receipt. Existing swapped
role must be refused or resolved before destructive metadata publication; it
cannot be treated as ordinary unswapped ARAM preload.
