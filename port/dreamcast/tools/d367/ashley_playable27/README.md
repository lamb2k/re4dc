# Playable Ashley PS2 rig (private qualification unit)

`ASHLEY_PLAYABLE_PS2_RIG=1` is a separate, default-off adapter for playable
`cPlAshley`. It requires `PS2_ASHLEY=2`, `NATIVE_MODEL_REGISTRY_PL_ASHLEY=1`
and the private `ASHLEY_PLAYABLE_PS2_RIG_DIR` generated by `rig_header.py`.
Partner Ashley's model3 predicate and distance LOD remain unchanged.

The owner must be `pPL`, OT7, model0 over 141 source joints and seven infos.
Every adopted player-family source BIN/TPL certificate, lifetime/revision,
skeleton and inverse bind is still reproved. Leon's model0/119-joint owner
cannot use this adapter. The generated slot map alone is not owner authority.

The source contract is body4/5, face7/9, hair6/B, skirt8/5, extraA/5, normal
right11/5 or r20e rightA7/A8, and left14/5 or15/5. The converter uses the
corresponding original PS2 members: body4, hair8, right11 orA8, left14/15,
TPL5/B/A7/A9. `Body->pWepHand` is not assigned a speculative archive tuple;
an unknown hand retains the existing whole-actor admission refusal.

Run Windows Python with numpy/Pillow:

```
tools/ps2_playable_ashley.py convert OUT --ps2-dat PL01.dat --gc-drs PL01.drs --right normal --left open
tools/ps2_playable_ashley.py finish OUT
tools/ps2_playable_ashley.py regcast CAST OVERLAY OUT...
tools/d367/ashley_playable27/rig_header.py HEADERDIR OUT...
tools/d367/ashley_playable27/source_gate.py PRIVATE_ROOT
```

Convert both `normal`/`r20e` right and `open`/`closed` left states independently.
Run the existing native stage and PS2-atlas alpha-mask pipeline before `finish`.
Registry generation uses `--slots --player-ashley --wide-identity --pool
--ch23-facts --pack-bones 96`. It needs no new package format, immutable alias,
role width or table ceiling. Both implicit PS2-rig metadata and explicit
`--ashley-rig` reject `--source-normal-length`; new normals retain only the
PS2-derived directions and magnitudes.

The full hand variants retain 4925/4951/5029/5055 triangles and 45 draw slots.
All authored skin influences survive; no surface transfer, truncation or
folding is used. Garments read the existing source solver's skin delta and
runtime inverse bind. No solver, simulation tick, gameplay RNG, movement,
collision or cloth scheduling is added or changed. The existing precise
playable face exception and OT7 skirt second pass remain in force. A neutral
PS2 face is drawn; new expression animation is not claimed.

`source_gate.py` checks exact PS2 triangle position/normal/weight/UV multisets
and atlas colour/alpha texels, plus malformed authoring contracts. Synthetic
posed diagnostics are not gameplay/look approval. `pack_gate.py` (WSL Python,
g++) runs the actual target validator with current narrow play identity flags,
slot/skeleton/family corruptions and an optional unchanged Ganado control.
It reports the compiled role layout instead of inferring target capacity from
host pointer sizes.

Full geometry is used for all proven player hand states. There is no measured
benefit for partner-style distance rungs at the close playable camera, so this
unit does not enable playable LOD. Existing gameplay animation data is unchanged:
the pinned active `pmrest25/em/pl01.drs` carries 86 FCV and35 SEQ members matching
original PS2 pl01. The prepared archive's 13 required normalized BIN/TPL members
also match the source identity inputs exactly. This provenance does not certify
unrelated baseline actors or assets.

Private receipts, complete source pins and reproduction helpers live outside
Git. SDK flags/preprocessing/object/ELF/raw identities and exact static/arena
deltas must be pinned before guests. Live look, gameplay, heap/KOS margins,
MODELLED timing and physical console acceptance remain separate pending gates.
