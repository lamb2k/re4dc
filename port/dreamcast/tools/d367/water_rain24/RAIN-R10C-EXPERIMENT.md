# Private default-off r10c native rain experiment

`RAIN_R10C_DC=0` is the default. There is no production recipe or data change. This unit adds only `src/game/filter06.cpp` and `port/dreamcast/game/effects30.mk` runtime/wiring changes. B selector tools stay at their independently reviewed d291 contract; the earlier read-only A receipt e7f2a60b remains separate. No SDK, Flycast, target image, live transition, loaded-asset ancestry, pixel or speed qualification is claimed.

The option is strict0/1. ON explicitly requires RAIN_DC=1, RAIN_PS2=1, D349_RENDERER_STACK=1, PVR_STREAM=1, NATIVE_LASER=1 and EFFECT_SPRITES=1. Only filter06.o receives the new definition. The renderer-stack requirement matters: gx_stub's ADEB flush is under that guard, beyond the older rain prerequisites.

The actual Filter06Render OT callback admits room10c only with the retained controller state1100 particles, target170/170/170/80, rate1, scale1, speed(21,-250,0), alphaMin0, nonnull particle storage and nonzero current alpha. These fields match the sole decoded GC EFF7 SST2 Kind1/generator44/Id1 record (SHA13511d82e6f8b50523123ccc0c6de66473a2fc21db2cdec0d8da3b16bbf2d3cb). The state signature is not a receipt proving currently loaded original record bytes; unretained random-speed fields are not authenticated. Player owner3/EST2 and room owner1/EST3 are independent effects, not this ambient setter.

Extra persistent state is exactly two u32 words: queued room and callback frame,8 bytes. The existing pending/alpha fields and fixed native pool are reused. main.cpp calls Render, then SetPrimBuffPtr/ClearOt, then increments Frame_cnt. Render runs effect/filter OT0x12 before synchronous GXSetDrawSync(ADEB); gx_stub drains source draws and calls the rain flush before Render returns. Therefore the ticket stamps Frame_cnt in the callback, not in prior Trans registration. The host controls lock these actual excerpts/order. This proves that bounded source ordering; it is not a PVR/present/image transaction or asynchronous scene lease.

Every new callback cancels an earlier r10c ticket before selecting a replacement, without erasing a new night ticket. Any Filter06SetParam call (including same-profile rebind/count0/destruction) and RoomInit cancel outstanding r10c tickets. Flush checks room/frame/profile/current alpha plus indoor, blur permission, full512x448 Screen and pause-filter gates again, then consumes once. A skipped/no-callback frame creates no ticket. A stale frame/room/profile or permission loss discards it. Normal wrap values0 and UINT_MAX are supported by equality and one-shot consumption; arbitrary ancient same-number frame reuse is outside a ticket's allowed same-Render lifetime.

Stop08000000 keeps drawing r10c while freezing source movement/alpha and setting private pool dt0; its frame anchor still advances so unpause does not accumulate stopped time. Original cParticle06 init/move, Filter06Trans, controller simulation/RNG and exact11b1600/170/60 subset predicate are source-identical. The option OFF preprocesses to the original full file. With ON, old-night expressions remain the original path; controls compare entire mock pool/packet snapshots in a night-only history against the baseline. The shared private pool naturally acquires a different history when the new r10c renderer actually runs; this is not a claim that later night images after that new history are bit-identical to a run with no r10c rendering.

The r10c render profile is deliberately experimental: source alpha normalizes against80, native RGB is210 and pool alpha gains120/100 relative to the old180/100 night profile. Actual PS2 r10c SST2 Esp08/C5 sheet metadata motivates those values; streak geometry, per-drop alpha/depth and the gain mapping are approximations, not a PS2 sheet conversion, source ancestry admission or exact appearance claim. No texture assets, uploads, converters, Esp08, cloud/esp_sub or GC native_ui code change. Root owns later target builds, matched source-informed stills/lifetime/memory/performance gates and user look approval.
