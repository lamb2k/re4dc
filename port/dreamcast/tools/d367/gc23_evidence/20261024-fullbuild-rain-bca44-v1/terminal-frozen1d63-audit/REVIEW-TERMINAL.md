# Terminal producer and catalog census — frozen 1d63

Source-only review of `1d63cffe3a232c402418f2f2d919e7abae476957`. This is a root-reviewable plan, not runtime implementation or terminal qualification. No SDK, target, guest, asset, recipe, allowance, or shared-source changes. The independent fixtures use actual extracted functions with deterministic mocked providers and public synthetic bytes. They establish source schedules, not observed guest bugs.

**Verdict: existing `re4dc_gcasset_finish` cannot establish terminal quiescence.** It closes diagnostic audio admission, drains currently latched observations and emits END. It does not stop the producers. A qualified fixture needs a permanent admission barrier, completion acknowledgements from real producers, a safe final drain, and a memory-only late-attempt fault latch. The latter safeguards do not replace stop/join. No full I001 acceptance is implied; Motion remains unwired and catalog ancestry remains independent.

## Catalog ownership and actual caller contexts

`gc_asset_disc.cpp:13-18` retains one shared `disc_catalog` file handle; disc_read performs fs_seek then fs_read in a Re4dcIoScope with no owner assertion or pair serialization. ensure `31` lazily installs streaming index; retire `44` closes the shared handle. At this frozen source, retire_disc_catalog has no runtime callsite outside declaration/definition. Do not report its race as an observed current bug.

`include/gc_asset_index.inc:25` reads a validated 112B row, but does not compare the returned row to the checked token's original row identity. `gc_asset_gate.cpp:143` describe_checked checks epoch before the row read, with no post-read recheck. Actual KOS fs_iso9660 `iso_read:698,714` takes fh_mutex for read; **iso_seek:863 changes fd->ptr without that mutex**. Even separate per-operation locking would not make seek+read atomic. Re4dcIoScope only protects cancellation/lifetime.

Actual binding/description census: UI gcasset_flush performs texture/member/payload/bank catalog work; glyph/texture/static/view/mesh/world/PCL/R4TI/shell cold capture, original member capture (`src/game/model.cpp:1560` before calcModelAddr), native movie open, compiled/startup/registry/PL08 owners also bind cold sources. Source TaskScheduler waits non-ISR tasks before parent resumes. The only frozen iTaskExec callers found are DVDReadProc and room decodeData; neither directly performs catalog bind/describe in its callback body. Audio 5ms keyon paths only take/complete immutable tickets; audio stream reader and hand job worker publish pending metadata/digests, not catalog rows. bank_pump's actual catalog resolution is invoked from UI flush. A different KOS thread identity is therefore not by itself proof of a currently reachable dual catalog reader.

**Confirmed interface hazard, bounded reachability:** an independently compiled fixture uses actual disc_read and actual gate/index code with a public, fully hash-valid ordered three-row catalog. Force A to seek row0, B legitimately seek/read row1 (leaving cursor at row2), then resume A's read. A's valid GC token receives the PS2 row2; actual emitted_checked suppresses its GC row and ends errors=0. A second control retires catalog during a read: describe_checked returns true although checked_current is then false. Normal sequential GC control emits GC. These are deterministic source schedules, not target/guest concurrency demonstrations. No current retirement caller or reachable simultaneous bind has been demonstrated.

The final coordinator must keep catalog and owner proofs alive until all producers and catalog operations finish and final accepted prefixes flush. Future Motion/cold-thread use needs an explicit safe owner/serialized reader service or owner-local read contract and post-read epoch validation. Merely releasing Motion mutex is not proof of safe caller ownership or no SQ/G2/IRQ. No RAM catalog, resident key-digest table, generic new mutex, or preload-all-keys assumption is authorized. Root must select and review the concrete mechanism before adding concurrent callers.

## Proposed fixture protocol (not implemented)

1. Latch terminal request using existing fixture interface; enter coordinator only after the complete normal frame, stream close, Render_swap and postframe bookkeeping. Establish main-owner thread, IRQ enabled, no SQ window, no G2/LH/audio/source-pump borrow. Do not run next TaskScheduler/render work. Retain owner records and source buffers.
2. Permanently close **new gameplay producer admissions** for source task/DVD/ARAM stream issuance, draw/deferred enqueue, movie start/poll, hand room/equip/refill, audio native reader refill and keyon. Already-issued completions and explicitly owned teardown I/O must still progress. Current APIs lack a single real barrier; enumerate each acknowledgement rather than treating a boolean or queue count as proof.
3. Finish source sound reset/stop while original stream work remains alive. Drain pending DVD/ARAM source callbacks including the local batch and inline path; prohibit callback reissuance after stop. Park audio5 at a g_lock-checked boundary only after required source callbacks/voices are completed or explicitly canceled. Park stream10 after its actual in-flight read/capture/publication is acknowledged. Closing diagnostic audio admission alone is insufficient. A saved callback pointer/NULL store is insufficient.
4. Tear down movies on their owner after reader scopes have returned: stop/destroy joins DMA service through stream_sem; preserve partial START/ticket errors. Complete source task/DVD cancellation with borrowers and native I/O leases retired. Preserve scheduler/IRQ progress during waits. Do not destroy work objects while callbacks can refer to them. Allow only explicitly owned world-loan teardown reads, then close that maintenance admission.
5. With draw/refill stopped and audio worker parked, invoke existing hand yield with no other locks. Join the actual job before freeing job memory/cells. No subsequent poll/enqueue/slot publication is permitted. Drain/cancel remaining unsent renderer work explicitly; flush previously accepted prefixes and require closed direct/SQ state and real GPU ready before retiring owners.
6. Close diagnostic audio admission under existing g_lock after required captured completions have become queued observations or explicit failures. Disable handoff/new room visit. Drain texture/member/payload/bank/core observations on coordinator outside all protected contexts while catalog remains installed. Verify per-producer acknowledgements and no callback/local batch, native I/O borrower, issued job, movie reader/DMA or accepted deferred publication remains. A zero queue is necessary but insufficient.
7. Only now call finish for the final visit, then permanently seal it. Never open another visit or migrate a late accepted prefix. All post-seal producer attempts must latch explicit failure memory-only; safe coordinator reports failure with original room/visit/producer identity. A no-output canceled operation must not invent acceptance. Keep final late-fault checking meaningful until producers are actually parked; an END log followed by a trace cutoff cannot prove silence.

This requires root-owned runtime API work and host controls before guest qualification. Current fixture/bench result loops and guest pause do not meet it. A timeout is FAIL/outstanding, not success; no arbitrary quiet interval qualifies termination.

## Cost, bounds and exclusions

No extra resident cache, digest table, pose snapshot or new thread is proposed. A common terminal state/epoch/ack/fault record would be four u32 =16 raw SH4 bytes, **not a complete priced implementation**: per-service active/pending acknowledgements may need more words, and API/compiler/alignment/target costs remain unpriced. Prefer existing thread handles/generation ownership; detached audio workers need cooperative acknowledgements or a separately reviewed joinability change. Reuse existing12KiB audio,6KiB stream and6KiB hand worker stacks. Actual callback local batch is8×16=128 raw SH4 bytes; it already exists. Existing hand job payload is12580B plus32B motion-owner prefix before allocator alignment, not new terminal storage.

Do not allocate another worker stack or full queue snapshot. Main selected callchains, ISR/source task stacks and changed coordinator stack require real target pricing. Existing joins, mutex waits and stream_sem wait have no aggregate terminal deadline. G1 lock may fatal after30s and DVD commands/retries/BIOS reset contribute further; a single command limit is not a global stop bound. Root can apply a bounded fixture watchdog that explicitly fails and retains outstanding identity, never certifies unfinished work. Current profile flags are pinned separately; alternate CABIN/movie/hand-retain/audio backends require independent stop coverage. No speed, memory-floor, hardware, guest, visual or full terminal PASS is claimed.
