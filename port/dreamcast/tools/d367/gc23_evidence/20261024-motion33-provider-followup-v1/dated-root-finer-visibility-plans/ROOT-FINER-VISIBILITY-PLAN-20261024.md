## Preserve production batching

Current chunk_ok rejects every non-null pvs_set. The placement-start pvs_cur is captured before queued earlier sources necessarily emit. Merely attaching a new set everywhere can lose SELECT_ONLY, REPLAY_LEAN and SUBMIT_BATCH across later geometry while still missing newly committed source receipts.

The candidate design, subject to source review, leaves the complete v1 path unchanged. A separately typed fine path first checks authenticated candidate presence for the current physical placement/part/cell. Unaffected parts retain normal batching. For an affected part, drain prior queued parts in their original order, then obtain a fresh scene/frame/generation/source-prefix and actual-affine decision. Never use queued source expectation or the stale placement-start snapshot as authority.

Only a qualified affected part takes the direct path, with per-let lookup after unchanged error selection and nonempty-LOD fallback and before bind/gather/transform. Failed guards draw normally; absent tuples/cells draw all. Any operation that can yield or invalidate proof state requires renewed checks at the actual decision. No new Pick fields, replay layout, relaxed chunk_ok, changed transforms or vertex format is authorized by this plan. Source-target cycles and targets at/before the source prefix are refused.

Price drain/query/direct-fallback cost against the actual saved selected work. A smaller triangle count alone is not a speed result. Do not assume all-world de-batching is acceptable.
