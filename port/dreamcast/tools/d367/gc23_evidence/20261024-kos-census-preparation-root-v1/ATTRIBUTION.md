# Attribution contract and limits

This is a new matched diagnostic, not another original KOS squeeze gate or a proposed memory fix. Both arms use the original ordered QA arguments plus `KOS_CENSUS=1`. The compiled squeeze module stays enabled; held bytes and fragment mode are zero, and any future fixture must use `squeeze 0 0`. No fixture, stage or guest is created here.

Mode 1 wraps malloc, calloc, realloc, memalign, free and scalar/array new. It does not directly wrap aligned_alloc. Source mode 2 adds the direct aligned_alloc wrap, peak snapshots and thread stack painting; mode 2 is excluded. Future final ELF checks must establish the existing aligned_alloc -> _memalign_r -> wrapped memalign and _malloc_r -> wrapped malloc paths, the corresponding calloc/realloc/free paths, and each wrapper's real provider reference. Symbol presence or an expected linker option alone is insufficient. Unknown opcode shape, missing edge, alias provider or unexpected link graph refuses completion.

The existing `kos_census.o` is already present as an empty object in the original mode-0 QA graph. Enabling its body does **not** add another raw game object. Expected raw object counts remain OFF449 and ON455; the existing ordered14-overlay pipeline remains unchanged. The seven new allocator wrap options must be the only additions to the previously recorded wrapper graph. The static census tables themselves consume target RAM and change programme/arena placement. Actual linked size/end and providers must be measured after root allocation; no modelled footprint is presented as a target result.

Host controls compile the exact unmodified `kos_census.cpp` body at mode1 using fake IRQ headers and allocators. The real table replaces an existing pointer rather than counting it twice. Scalar/array new call the real provider then only reattribute the inner allocation; a wrapped-malloc inner provider is counted once. A failed nonzero realloc retains the old block; successful movement replaces it; size-zero behaviour drops it. Null free does not change the ledger, though it is forwarded. Memalign arguments and null failures are forwarded, not validated by the census; target allocator alignment is still the real provider's responsibility. These host controls do not establish target ABI, concurrency or IRQ behaviour.

The live table is bounded4096 entries and the log aggregates at most256 caller rows. Any `lost` or caller-row `overflow` makes coverage UNKNOWN. The actual source also uses unsigned32 requested-byte totals without checked arithmetic; a synthetic UINT_MAX+1 case exposes the wrap. Invalid/out-of-range sizes, inconsistent row sums, nonunique lifecycle groups, incomplete ring data and arithmetic inconsistency must remain UNKNOWN. Link coverage never establishes runtime allocation coverage, allocations made before observation, allocator-private allocations, or direct/internal paths not intercepted by the final graph.

At a future lifecycle observation, bind the exact instrumented ELF/main/all14 identities, phase/room and full census header/rows. Resolve each caller using that ELF. Require row block/byte sums to match the header and zero loss/overflow before reporting the bounded requested-byte ledger. The current source arena is one successful memalign call in `platform/mem.cpp`. Exclude it only when the exact binary callsite is authenticated, its row has the expected single block, and its requested size equals the actual arena allocation recorded by that run. Do not exclude every allocation in a broad caller range or silently subtract the old run's arena size.

Report remaining caller-requested bytes separately from mallinfo/KOS used/free/break/largest-block values. Mallinfo allocated bytes include alignment, allocator rounding, headers and other internal/unwrapped allocations. Subtracting the authenticated arena **requested** size from mallinfo used leaves its allocator overhead in the residual; label that residual explicitly. Do not call it exact non-game-arena allocated bytes. Unreconciled bytes are UNKNOWN, rather than automatically attributed to GC gate storage. Live caller attribution, source tables and linked static growth are separate evidence. No performance gain, original48KiB qualification, original memory PASS or physical acceptance follows.

Current historical header omissions are pinned afresh before this new build. The original missing prehash and raw hair-header mismatch remain unchanged. The invertible LF-to-CRLF bridge and root supplemental receipt are historical context, not a rewritten original input manifest. MMD dependencies omit isystem headers; the separately pinned SDK/compiler/sysroot scope remains necessary. Old transient generated SDK C files are source/driver-bound, without invented retrospective output hashes.
