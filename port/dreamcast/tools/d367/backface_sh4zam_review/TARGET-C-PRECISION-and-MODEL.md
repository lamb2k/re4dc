# Target C arithmetic and complete kernel path model

The paired C programme source is main abcfc8a3d, with CPU_BACKFACE=1. The actual target world and actor `bf::strip` specializations each contract the determinant to FMUL, FNEG, FMAC. Neither platform compilation command contains `-ffp-contract=off`; GAME_FP_CONTRACT does not cover these platform translation units. This is actual SH4 object evidence, not an inference from the minimal compile.

World offsets a2/a4/a6 form the rounded second product `(By-Ay)*(Cx-Ax)`, negate it, then FMAC `(Bx-Ax)*(Cy-Ay)` into it. Actor offsets b2/b4/b6 do the same, with the two first-product factors exchanged. The parity negation and multiplication by +/-1 follow. All differences are rounded binary32 before multiplication.

The original strict host C oracle was insufficient for this compiled reference. The retained finite witness in FINAL-C-ARITHMETIC.json gives +0 with separately rounded products, versus -0.012209698557853699 with target-style fused arithmetic, changing the cull2 even-triangle decision. This witness uses host libm fmaf, not target execution. The SH4 software manual section 6.4 page126 documents the different single FMAC rounding: https://www.renesas.com/en/document/mas/sh-4-software-manual . The kernel owner has corrected both generic and fused loops and the target-style oracle; do not change the C reference flags to make the candidate pass.

The new `dynamic-kernel-model.py` imports the bounded actual-opcode interpreter read-only. It records executed instruction paths, including real taken branches, all back/split/terminal handling and kernel setup/exit. It applies existing AVK simulator issue groups/latencies, extended only for missing system-register and PC-relative operations. It does not simulate cache, external memory, SQ destination/TA stalls, FPU exceptions or calls into the kernel. It is MODELLED evidence, neither hardware timing nor a bound.

On exact FMAC07 trace-off object b35c978b (full hash in JSON), a 64-index strip costs 2580 modelled cycles world, 2590 explicit actor, 2721 whole-stream actor when all front. Per62 input triangles: 41.61 / 41.77 / 43.89. All-back costs 54.24-55.29 cycles/triangle; the retained mixed fixture costs 56.35-58.84. These include setup/exit, rather than claiming a steady-state inner loop result. The earlier object04 strict candidate model is preserved separately and must not be treated as the corrected FMAC result.

The four-cycle incremental target is not established and these figures do not demonstrate an improvement over the original 12/13-cycle actor emit-only loops. Whole C-path modelling and matched scene strip distributions remain open. Vertex reduction percentages alone cannot price a scene: strip lengths, split counts, clipping, eligible material count and actor scope are required. Leon, Ganados and El Gigante must remain separately tagged; no old class4 assumption replaces positive Ganado bursts.

Source review of the corrected FAST_STEP mapping confirms the same rounded-product/FM A determinant, with explicit SZ=0 around its single-register FR1-to-FR0 move. A fused candidate writes one pending B into the SQ before classification but issues PREF only on the correct committed path. The existing actual-object word/register oracle remains the required correctness gate. Future optimized bytes need a new source/opcode seal; this note is not automatic acceptance of later kernels.
