# Defensive catalog ownership and generation audit

Base: 1d63cffe3a232c402418f2f2d919e7abae476957. Isolated source branch wip/gc-catalog24-20261024; frozen gc-port23 remains unchanged. Root owns integration/target/terminal acceptance. No asset, recipe, stage, guest or Motion implementation changes.

The preserved terminal-next-audit runner reproduced two actual-body interface defects before this unit: nested shared seek/read could substitute a valid PS2 row for the requested GC row with errors0; describe_checked could return a row after callback retirement. These deterministic schedules do not prove that the current game reaches overlapping catalog callers. Catalog APIs remain owner-only; this guard is not a general cross-thread safety guarantee for all gate state.

The disc wrapper now owns each complete seek/read pair with a nonblocking atomic_flag. A contended, short or failed read invalidates the catalog and latches failure; it does no fallback/hot filesystem scan. Retirement first publishes Retired and advances/invalidates the core epoch, then attempts the guard. A busy handle is retained exactly and is neither closed nor reopened when the old reader returns. Repeated ensure calls remain false. Only an explicit later safe-owner retire can acquire the guard, close that exact handle and move to FreshInstall; that state is not Ready and does not restore old tokens. Only a complete fresh pinned install can become Ready. A failed close retains its descriptor and Retired state for another explicit retry. No deferred automatic close/reset exists.

The core snapshots callback source/extent/count/epoch. Index installation hashes and validates local state without provisional global catalog publication; an older core install failure cannot clear a successful callback replacement. The disc-service wrapper deliberately differs: a failed physical service install latches failure and invalidates any callback replacement, because it cannot publish Ready for that failed service attempt. Every read callback revalidates the captured epoch before bytes can be used. bind_checked returns only a captured still-current epoch; describe_checked publishes a temporary row only after current-token/epoch checks and clears its output on failure. Retirement invalidates before any later diagnostic. During native IO/read callbacks, catalog retirement/read/capacity faults only update bounded memory state; active errors are charged immediately. A fixed4-byte reason/owned-or-unowned mask formats at safe pump/END or before begin replaces the old visit/scope. Catalog replacement does not clear that mask. No logging occurs while Re4dcIoScope is active. The final18-bit epoch is an invalid terminal tombstone, never an install/token authority: retirement during the last admissible install remains distinguishable and exhaustion cannot wrap/reuse authority.

The index format, source SHA/provenance semantics, immutable CD contract and default-off gate are unchanged. No resident catalog/digest table, allocation, spin, FS under SQ/G2/LH or terminal protocol is added. New atomic disc state/flag and local snapshot costs need actual target pricing; ordinary host identity is not SH4 programme identity.
