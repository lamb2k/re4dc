# Selected immutable catalog and reviewed proof binding

Offline tooling only, based on 140a699f8ead7b406e76581de7075191acf77a96. `proof_catalog24.py` adds the source/provider binding layer missing from the generic `catalog_index.py` formatter; the latter, the strict judge, historical seed and runtime remain unchanged. Production GC_ASSET_CATALOG_SHA256 stays0. Generating an index/data option does not install it, prove accepted use, complete consumer coverage or qualify I-001.

## Exact inputs, no origin inference

The CLI requires pinned full SHA256 for a selected manifest and a selection recipe. Manifest rows are exact `{size,sha256}` pairs keyed by canonical relative disc asset names. Only explicitly listed providers are opened; the tool never scans stores, reads new guest failures or converts assets. Runtime programme/overlay providers are rejected. Pass explicit readonly store roots. Source paths must resolve to regular files inside those roots, match the selected full-file size/SHA and retain the same device/inode/size/mtime/ctime before/open/after. Full files are stream-hashed before and after payload reads. A path replacement with identical content also fails. Metadata rejects duplicate JSON keys; unexpected fields, unsupported providers and capacity failures abort before output allocation.

Selection schema1 has exactly `schema`, `manifest_sha256`, `providers`:

- `texpak`: exactly provider/asset/path. Asset must be `dc/tex.pak`; the bounded existing RE4PAK reader checks duplicate keys, all member bounds and overlap. Each texture identity is crc8-fnv8, and its full SHA includes every immutable RE4TEX header and payload byte. All selected pack keys are inventoried, not only historically loaded/resident keys.
- `file`: provider/asset/path/kind/id. Texture loose overrides must bind `dc/tex/<key>.re4tex`, with their own complete header/digest. The sound-stream provider is the actual conservative full `bgm/aica_str.dat` identity `kind=sound-stream,id=aica-str-dat`. Other supported digest identities use the first20 SHA256 bytes as40lowercasehex and retain full SHA. Caller review must establish that an exact whole file is the runtime-consumed identity; a matching filename is insufficient.
- `span`: provider/asset/path/kind/id/offset/bytes/sha256/boundary. Only model/motion currently supported. Offset/length and full span SHA must be exact; id equals span SHA[:40]. The whole selected parent file is authenticated too. `boundary` is `{path,sha256}` for a pinned separately reviewed immutable-boundary receipt. This recipe cannot discover trustworthy FCV/BIN extents from names: the runtime/provider owner must review the original complete span before preparation/REL/pose writes. Boundary or layout correctness supplies no provenance. External MTC shells and unproved inherited constituents receive no invented provider.

Model owner convention: kind=model, full exact original BIN member including header before calcModelAddr, id=first40hex SHA256. Motion owner convention: kind=motion, full exact original captured span SHA256, same prefix id. Role/layout selects the span only. Geometry/layout framed composites require their own exact runtime-compatible derivation proof; this helper does not automatically invent such a hash from filenames or package membership. `DIGEST_KINDS` format support is not a statement that every current runtime path is covered.

## Reviewed-origin authority

Without `--reviewed-proofs` and its exact pin, every row is Unknown, including PS2-looking paths, old heuristic PS2 labels and local VQ/mip/converter output. A reviewed-origin document has exactly schema1, selection_sha256 and entries. Each entry is exact kind/id/fullSHA/provenance/owner/reason/reviewed/chain. Provenance is gc/ps2/authored; reviewed must be literal true, reason+owner nonempty, and chain contains1..32 exact pinned receipt files inside permitted roots. Every chain file is hashed and identity-checked, each <=4MiB and total<=32MiB. Stale target payload, selection swap, duplicate origins or proofs for identities outside selected actual bytes fail.

**This is an explicit reviewed-attestation trust boundary.** Pins authenticate reviewed bytes and target binding; they cannot establish the truth of a human origin review. The integrator must independently approve the origin document and all constituent/derivation evidence. A receipt named PS2 or a successful parser/API/conversion is never a proof. Authored means reviewed original Dreamcast artwork, not arbitrary local modification of GC content. A correct boundary proof without a reviewed origin remains Unknown.

## Allowances are separate and can only shrink

Optional `--accepted-allowlist` is the independently reviewed last-accepted ceiling, with exact pin. `--requested-allowlist` may only retain exact full rows of that ceiling: scope/room/transition, kind/id/fullSHA/provenance, reason/owner/evidence must all remain identical. Duplicates, wildcard/new room, changed digest/origin/reason/owner/evidence or a nonempty requested list without an accepted ceiling fail. Rows absent from the selected exact catalog or upgraded by a reviewed positive proof can be removed; they cannot be rewritten. Output ordering is deterministic. No accepted ceiling means an empty approved allowlist.

The separate optional pinned `--historical-proposals` input preserves already-authored exact historical rows that match selected identities. It writes only `unapproved-proposals.json`; it never enters `allowlist.json`. The existing 2026-10-23 seed is proposed historical LOAD evidence, not an accepted allowance or emitted use. Resident-only rows confer no room entry. New guest failures cannot add rows: there is no log parser/auto-learn path. Nontexture omissions, changed loose payloads, startup/transition/Motion or unobserved rooms remain unapproved unless already present in an independently accepted ceiling.

## Private output and bounds

Use a new output directory outside readonly stores; existing output is refused. Outputs are catalog.json, deterministic gc-assets.idx, allowlist.json, unapproved-proposals.json, report.json and proposed data-option.json. The data option replaces only dc/gc-assets.idx in a future private fixture; it does not set a compile-time pin or alter production recipes. All validation precedes directory creation. Index build uses the unchanged128-byte header/112-byte row format, sorted exact kind/id/fullSHA, capacity16376 plus8 unknown quarantine slots. The freshly built file is re-read through the indexed Reader with its exact SHA before output. Two selected sources with one identity share one record; different full bytes under one texture key remain separate and gain no old digest allowance.

Runtime representation remains the existing source contract: one owned catalog FD,512-byte install hash scratch,112-byte record read,128-byte header,2KiB maximum Seen bits and8 unknown quarantine entries. Binary lookup requires at most bit_length(record_count)+1 record reads after installation. These are source bounds, not a fresh SH4 timing/heap/stack measurement; target qualification remains root-owned. The tool adds no runtime code/storage. Host metadata is capped16MiB/file; pack/source content is streamed in1MiB chunks, FD use is sequential (one immutable provider/evidence read at a time). Root runs host processes with <=256MiB address space and120-second limits.
