The diagnostic movie picture bridge hashes the complete validated route movie
container once per open. It opens a separate read-only handle and reads up to
40,000,000 bytes using 512 bytes of scratch; the original decoder cursor and
transport are unchanged. This is an additional full read and SHA computation,
not a claim of free runtime cost. Catalog binding happens after releasing the
native IO scope. No filename or movie API establishes original asset provenance.
A mixed or unproved container remains unknown unless its full exact hash has an
independently reviewed origin proof.

The UI binding records the actual texture pointer, active dimensions, monotonic
owner and checked catalog token. Every upload first revokes the prior upload
proof, then must complete under the same owner, pointer, dimensions and token.
The accepted `movie_draw` packet uses a scoped exact pointer/extent/address
observer, sharing only the generic packet observer mechanism with glyphs. There
is no ambient font, model or movie texture-range exemption. The proof's upload
version must equal the current completed UI upload. Successful texture frees
revoke it after existing refusal/fence checks; refused closes retain the live
binding. A stale writer revokes the current upload before its owner is rejected.

Only an accepted verified picture emits Movie and Texture acknowledgements.
Open, read, decode, upload and discarded packets produce no asset-use row.
Counters describe accepted-use acknowledgements, not decoded or displayed frame
totals. The source-extracted host controls exercise the real capture fragment,
UI binding/upload methods, draw packet and accepted observer, including changed
owner/version, same-address reuse, missing upload, wrong packet pointer/extent,
discarded send, unscoped address and serial exhaustion.

The current metadata adds eight bytes to Movie and a 28-byte UI proof plus its
four-byte owner counter on SH4. Additional code and final linked memory remain
unpriced until an allocated target slot. All additions are under the default-off
gate. No complete I-001 claim: actual room admission/checkpoints, remaining
static payload consumers, complete reviewed
catalog/allowlist and target/image/guest gates are still open.

The movie audio observer prearms the same checked movie token with its actual
stream handle and UI owner. The privately included KOS stream source is unchanged.
Both ordinary and CABIN starts retain their original calls and commands. Around
those calls, the observer snapshots the actual stream callback, two channel IDs,
sample RAM bases and 32768-byte ring, then verifies all three accepted stereo
START commands and the final stream state. The ticket is captured before the
first submission; an unlocked pump reports the copied token. Callback prefill
may read the disc, so no new audio/G2 lock surrounds the stream-start API.
Observed command submissions are guest-side evidence, not physical audible
playback or ARM acknowledgement.

An API start that submits no commands produces no use. Partial, rejected or
malformed commands, unarmed starts, cancellation or owner replacement during
prefill complete the ticket with an invalid token and explicitly fail. Stream
stop/destroy/shutdown revoke admission; a retired catalog token also fails at
the later pump. The fixed bridge only copies ticket/token values; it cannot
hash, log, open a file, allocate or spin while a command is submitted. Additional
observer state is approximately 80 bytes on SH4 before linking; final target
code and BSS still need allocated qualification. The special C object receives
the gate definition through a target-specific default-off make rule.
