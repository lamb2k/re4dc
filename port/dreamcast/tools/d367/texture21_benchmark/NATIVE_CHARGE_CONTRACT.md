# Native charge repair and canonical1004 stage contract

This supersedes the logical-only `guard()` charge in c4ced91ed. Preserve that commit and its sealed evidence. The old994 CRC hold remains; the new canonical1004 is a separate source/pack/programme family, not a relabelled old receipt.

`file_charge.ChargeSession` conservatively rounds logical sizes of every unknown file, failure, partial and metadata file to the native volume allocation unit. It rejects symlinks, junctions, unknown reparse points and outside paths. Only explicitly declared closed-image credits may use native compressed bytes. Credits require a root-allocation-pinned receipt SHA, exact1743 readback receipt SHA, matching plan/arm/image/fullSHA/size, same volume/fileID/creation time/single link, and the exact expected arm image identity. WOF compressed files are permitted; symlink/junction reparses are not.

A `WinPin` opens the credited image with **read access only, share-read only**. It hashes the whole logical image once through that handle, verifies file identity, and holds the handle until the writer finishes or fails. Concurrent write/delete opens are denied. Every charge refresh checks the same fileID/link count and calls native `GetCompressedFileSizeW` afresh, rounded to the volume allocation unit. This is available only to the Windows writer; a WSL process cannot silently substitute POSIX block counts for native compressed credits. Fresh C free bytes and the unchanged18GiB+64MiB runtime floor remain independent requirements.

The root allocation receipt now also binds exact `allocation_cap_bytes`, `peer_reserved_bytes` and `allocation_root`; command arguments must match. `charge_credits` is an optional list of `{receipt_path,sha256}`. First M1 has no credits and retains the1.2GiB cap. After M1 fullreadback and root NTFS compression, `ntfs_image_readback.py` produces the new native-file-identity receipt. Root then approves a concrete two-arm aggregate using actual M1 native charge plus M0 prospective uncompressed writes, metadata, failures and current peer reservations. The code never assumes both arms fit1.2GiB or raises a cap.

Atomic publication uses Windows `MoveFileExW` without REPLACE_EXISTING, or POSIX exclusive hardlink creation followed by removing the writer's own partial name. An existing target always stops publication; it is never overwritten. Failed partials/final outputs and failed metadata writes remain charged. Prospective file bytes are checked every chunk; expensive charge/free-space probes remain <=5Hz. Final writer receipt allocation is checked before its exclusive write.
