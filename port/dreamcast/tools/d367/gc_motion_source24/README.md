# Immutable Motion source foundation (source only)

The default-off `RE4DC_GC_ASSET_MOTION_SOURCE` option requires GC_ASSET_GATE and GC_ASSET_MOTION_UNKNOWN. Root owns Make, common-slab integration, final protocol/terminal and runtime gates. No wired bit changes. The original UNKNOWN detector stays active, including when a captured contributor can be named. This is not I-001 completion, a real catalog inventory, a speed claim or runtime acceptance.

## Original identity and evaluation

Exact original source spans are tagged `motion`. The id is the first 20 SHA256 bytes as 40 lowercase hexadecimal digits, with the complete SHA256 retained. Missing rows stay Unknown through the real catalog binder; neither FCV/BIN/EVD/EVS layout tags nor file/API names imply PS2. Successful MRAM read bounds are used; MRAM+ARAM lengths never become one invented allocation.

Read.cpp captures core, room, enemy, player and weapon FCV/EVD/EVS/BIN members before any bind/prolog or pointer writes. Each span ends at the next member, REL boundary or successful original-read end. Duplicate captures never rehash prepared bytes. Fresh FCV/Shape captures validate all original relative key offsets and bounded three-axis Hermite blocks against the real Fcc stride formats. The actual evaluated key pointer is validated independently; header membership cannot bless rebound or external keys. Generic `motion_source_note` only accepts bind/EVD constituents, never FCV/shape headers alone.

MTC archive prefixes receive no source identity and are not emission evidence. Native motion load captures the complete original external FCV after full-read, CRC/FNV and prefix checks, before pointer rewriting. Its stable Slot owner and a fresh source serial bind the original full SHA to the proxy. Catalog publication occurs after acquire's motion mutex is released, while its lease pins Slot and Binding. Discard revokes before free/slab reuse using fixed metadata only. Already accepted uses retain their old checked identity until an unlocked flush; new/deferred stale uses fail closed. No Slot enlargement or new backing allocation is introduced. Cold original SHA/prefix/leaf validation is extra work and has not been timed on target.

MotionMoveCore notes actual successful pose samples. CameraMotion notes actual evaluated key spans but requires a separate real selected-view boundary. Shape output is reset only after the real neutral memcpy, then adds only nonzero channels with actual vertex writes. Geometry-owner callbacks independently authenticate original BIN delta spans and successful prepared-buffer publication. No hidden/evaluated-only or zero-record path emits a use.

## Storage and replay contract

Root supplies a 12,288-byte, 32-byte-aligned partition with `motion_source_storage_bind(base, bytes)` at cold startup before any original loader captures. It placement-initializes only supplied storage, with no allocation/hash/catalog IO. Repeating the same base preserves generations; another base fails. The common slab remains process-owned; room/source/subject generations retire separately. Large helper BSS was removed. The host IA32 ABI control reports State 11,928 bytes and just 8 bytes of pointer/bootstrap BSS; the production 32-bit static assertions enforce State <=12,288 and MotionReceipt 64 bytes. This host layout control is not SH4/KOS object qualification.

Capacities remain 128 source identities, 64 subjects and eight contributors per receipt. Overflow never drops an error into a zero-use proof. Root's full diagnostic proof profile partitions the existing 32 KiB metadata region into geometry 12,288 + Motion 12,288 + remainder 8,192; the draw-plan cache is explicitly disabled only for that profile because its table/local floor does not fit. The common 64 KiB allocation and packet regions stay the same. Cold allocation timing/peak and whole-unit KOS/correctness remain root gates.

`MotionReceipt` freezes model/info/view pointers and generation witnesses with original source serials. A receipt-constructed MotionSourceScope sets explicit frozen replay mode. Nested model/info scopes validate the saved witnesses and preserve the frozen contributor set; they cannot resnapshot a newer model. Stale/reused/different subjects reject to an empty fault receipt. Accepted intervals copy receipts and latch fixed metadata; hash, catalog read, log, allocation and spinning stay outside protected contexts. Root must freeze the receipt at actual deferred enqueue and replay it at the actual accepted producer.

`re4dc_motion_gcasset_idle()` is a finite witness for an idle motion mutex, no owner leases and no pinned slots. `motion_source_idle()` refuses live render/deferred scopes, real ordinary evaluator stacks, persistent counter overflow/underflow, unbound storage and unflushed accepted latches. Root must first stop real game/model producers and drain its renderer/audio/worker paths; empty current state alone is never proof that producers stopped.
