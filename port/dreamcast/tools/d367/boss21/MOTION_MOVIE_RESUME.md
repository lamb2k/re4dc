# Bounded movie motion restoration (H056)

This is a separate default-off successor to the frozen accounting/packing candidate. It repairs one demonstrated shared-code lifecycle omission: movie staging can evict heap-backed FCVs, but the prior path waits for normal gameplay to fault each clip back in. The source gap is confirmed; it has not been established as the cause of the reported console stalls. The genuine after-s20 churn has a separate reserved-storage fix and acceptance window.

Enable `MOTION_RESUME=1` with `MOTION_PRESSURE_BACKING=1`, `MOVIE_HEAP_EVICT=1`, and `ROUTE_MOVIES=1`. Default zero contributes no new build flag. No recipe enables it here. Accounting and packing commits remain independent; integration into a current full program is a separate qualification.

The runtime records successful source acquires in the current and previous source frame, intersects them with actual movie-owned heap-key evictions, and carries binding generations to the final route boundary. Bind preloads, reserved FCVs, normal pressure/OOM/weapon victims and unrelated hot keys are not a requested resume set. Native movie finish only queues metadata. Restoration runs after movie buffers, model/weapon/world loans and source end callbacks, immediately after the route's `SceEventEnd`, before it returns to normal gameplay. Skip/cancel clips merge still-current tickets until that final boundary.

Every request is checked again under the loader lock. Retire/rebind, individual dead-heap key retirement, source age, wrong heap, menu hold and nested ownership invalidate or refuse it before borrowed metadata is used. Menu hold cancels the journal; existing room-resident keys remain governed by the original suspend/restore path. This adds no blind menu rewarm. Cabin's custom movie lifecycle is excluded. Long stepped/QTE source intervals can age out the set; future attack choices are not predicted.

Admission preserves the existing aggregate heap-payload cap, cold-pool/spill margins, strict-v3 no-spill policy and pins. The entire missing set must fit the current cap and one conservatively sized free region (aligned payload plus 64 bytes per allocation), while retaining the applicable cold margin. A refusal performs no I/O and no eviction. During reads, each allocation rechecks physical free/largest space; an external allocation race can leave a partial set, logged once, without OOM/pressure eviction or a retry loop. Prepared heap blocks use the existing FCV reader, retries, CRC/FNV/proxy/offset checks and relocation path. No FCV moves, slab sizes, archive format, source motion selectors or gameplay flags change.

Tracking is fixed metadata: the tested journal is 424 bytes and its queued tickets 144 bytes, plus one boolean. The SH4 object check measures 569 bytes additional BSS. No per-key payload reservation or archive allocation is added by tracking. Restore payload is ordinary reclaimable heap ownership counted by the existing cap; it is not fixed reserved backing.
