# Bounded owner-attributed pre-skin witness

Private-QA diagnostics only. `ACTOR_VISIBILITY23_WITNESS=1` requires the existing
`ACTOR_VISIBILITY23=1` experiment. The new toggle defaults to0; no production
recipe changes. It does not change culling, source identities, geometry,
gameplay, timing/presentation policy or the existing600-bind window. Main owns
integration, actual programme/asset/image review and later runs.

The witness identifies actual synchronous owner id0x2b after the original
material/view/epoch admission. It copies the actual owner address, cModel
serial, source lifetime epoch/serial, flags, first-two-ModelInfo body/head role,
room, game/UI clocks and the selected LOD/meshlet/source-record identities.
The owner identity/lifetime is checked again before the query returns to its
caller. Other admitted enemy owners are counted as unattributed to this boss;
pre-material/view refusals are outside this diagnostic cohort. This is not an
exhaustive count of every boss part or every draw.

Current posed lo/hi and exact float32 view12/P7/viewport6 words are copied after
the existing bounds calculation. The read-only hook in the actual world-ready
getter copies the field it actually selected, actual receipt source/storage/
metadata/epoch/stamp/UI/scene/FPSCR/coverage/required mask, consumed current
values and final placement-integrity result. Field0/stage0 means no field or
ready evaluation occurred; no eye-cell or receipt is guessed. Stages1..5 are
scene, cell, receipt, metadata and placement. A positive potential requires the
actual successful final snapshot. The hook borrows source state synchronously;
persisted addresses are numeric identities only and are never dereferenced
after that query.

Mode1 records potential and draws. Mode2 actual position/triangle skip counters
are committed only in the two existing caller branches immediately before
their original counters/continue past position processing. A return-true query
without that caller commit, wrong path/LOD/meshlet/count, duplicate commit,
nested/incomplete query, identity reuse/change, mode/workspace/clock mismatch,
invalid/missing positive receipt, counter overflow or serial wrap makes the
window unqualified. Those diagnostics cannot change the original draw/skip.

No allocation, per-vertex work, polling or unbounded record list is added.
One fixed state has a compile-time4096-byte cap. It holds one actual boss
lifetime, two role summaries and at most four first bounded samples: first
kept and first potential section per role. In mode2, sampled potential records
are marked committed only by the real caller branch. The first examples are
not a history of every pose or every meshlet.

At completion/cancellation only, at most39 extra rows are emitted: one
`AV23OWNER` summary, two `AV23OWNER_PART` summaries, and up to nine rows per
sample (`SAMPLE`, `SOURCE`, `ADDR`, `BOX`, `VIEW`, `WORLD`, `RECEIPT`, `COVER`,
`RANGE`, all prefixed `AV23OWNER_`). Native formatting uses256-byte lines; host
controls test maximum32-bit counters/addresses and the complete fixed report.
`BOX`, `VIEW` and `RANGE` use raw float32 hexadecimal words. At most9945 text
bytes are formatted. The old AV23/WORK/WINDOW rows remain unchanged.

`qualified=1` means a completed600-bind diagnostic cohort with a stable actual
2b lifetime and no witness failure. It does not mean hidden work was found,
pixels match or a framebuffer displayed. Inspect potential/skip counts
separately. Mode0 can complete but cannot obtain an admitted bounds witness;
it remains unqualified with no boss section claim. No completion report,
truncated/missing rows, parser/ring overrun, overflow, cancellation, or absent
owner must not be promoted to complete evidence. Failure bits are1 incomplete,
2 overflow,4 query/commit pair,8 identity,16 sequence,32 context. Later adapters
must bind exact source/programme/window/rows and keep pixel/performance/memory
acceptance separate.

Host controls:

```
AV23_WITNESS_TEST_OUT=<owned-small-scratch> \
AV23_WITNESS_SDK=<existing-retained-SDK-root> \
python3 -B -m unittest discover -s port/dreamcast/game/tests/actor_visibility23 \
  -p test_owner_witness.py -v
```

The controls compile/execute the actual bounded state, extracted actual owner
bridge and ready getter, plus the actual diagnostic helper API and both actual
native caller branch fragments. They test partial/lifetime/receipt/overflow/
wrap/duplicate/refusal cases, the bounded native formatter and default-off Make
gate. All five changed runtime files preprocess to the baseline token stream
when witness0 with actor visibility enabled. Actual host helper allocated
sections match the bea2 baseline and contain no witness symbols with witness0.
Host objects are not SH-4 object/programme identity. No target object, full
build, disc, stage, guest, actual boss cut, pixel match or timing is established
by these controls. The retained SDK is read only, never copied.
