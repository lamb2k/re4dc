## Close and cancel

WHO B-cancel (`ss_pzzl.cpp:2711–2716`) changes UI state only. Closing inventory after an earlier successful heal must still commit that reset; “cancel” is not a rollback of consumed items or global health. Ordinary UI exit chains through `SubScreenExit` (`src/Sscrn/ss_main.cpp:431–432`) and reaches the common core close at `sscrn.cpp:735`.

`SubScreenMiss` handles a rejected task-slot request before any swap (`sscrn.cpp:315–319,383–396`): there are no reset requests from that unentered session to apply. A rejected second open must not erase an already active session's pending requests. Initialize state per successful backing open, clear it exactly once after close, and retain none for the next room/session. `systemResetCommon` also calls `SubScreenExitCore` before `TaskAllClear` and `ReleasePlData` (`src/game/main.cpp:672–675`); the same verified restore/drain point handles that path before actor teardown.
