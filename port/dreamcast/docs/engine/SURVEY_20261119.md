## Techniques

### Cache and data layout
- **Half the data cache as the per-meshlet vertex buffer (DCA3).** Each stage writes in place into an 8 KB cache-RAM area at 64 bytes a vertex; submission reads from it. Meshlets are at most 128 vertices, built offline. Source: `vendor/librw/src/dc/rwdc.cpp` in the DCA3 repo; https://softwareengineeringdaily.com/wp-content/uploads/2025/04/SED1825-GTA3-on-Dreamcast.txt
- **Quantised vertex streams (DCA3).** int16 positions, int8 normals, int8 UV indices into a 256-entry table. Same source.
- **Several small stage loops over small blocks** (32 vertices worked best for the author). https://dreamcast.wiki/Fast_SH4_Vertex_Processing
- **`movca.l` on lines that are fully overwritten, `pref` on sources.** https://dreamcast.wiki/Useful_programming_tips
- **What a miss costs:** a 32-byte line fill is 7 to 12 bus cycles. Align matrices to 32 bytes, keep co-used data within 2 KB, and avoid hot buffers a multiple of 16 KB apart. https://dreamcast.wiki/Efficient_usage_of_the_Dreamcast_RAM
- **The KallistiOS half-cache regression** (about November 2023 to mid 2024). https://www.thedreamcastjunkyard.co.uk/2024/07/playstation-emulation-silent-hill-3.html
- **Batch matrix work:** load the matrix once, transform an array, swap back (DCA3, podcast transcript above).

### Submission and clipping
- **Clip class per object, then per meshlet, by bounding sphere (DCA3).** Outside is skipped; only boundary meshlets take the clip path.
- **Batch transform that returns "all in front of the near plane" (Wipeout).** https://raw.githubusercontent.com/jnmartin84/wipeout-dc/main/src/render_dc.c
- **Header reuse:** precompiled headers per texture, re-sent only on change (Wipeout, DCA3).
- **Store-queue and chip timing:** a flush waits for that queue's previous flush; a 32-byte burst can stall up to 500 bus cycles when the chip is busy. Put work between flushes. https://dreamcast.wiki/Fast_SH4_Vertex_Processing
- **KallistiOS 2.2:** hybrid direct / DMA submission, a faster `pvr_prim()`, `pvr_send_to_ta()`, `opb_overflow_count`. https://raw.githubusercontent.com/KallistiOS/KallistiOS/master/doc/CHANGELOG.md
- **W-first transform** so the perspective divide starts sooner; reciprocal square root in place of a divide. https://sh4zam-com.elysianshadows.com/tips.html

### Visibility and detail
- No open Dreamcast project was found that documents baked visibility, portals or occluders.
- **Two-level sphere culling (DCA3).**
- **Lights moved into model space once per draw** (DMS-Engine, DCA3), so normals are never transformed.
- **Simulant's budget:** under about 50,000 triangles on screen, ambient plus one directional light. https://simulant-engine.appspot.com/docs/guides/dreamcast.md

### Memory and streaming
- **No runtime conversion (DCA3):** the build repacks models and textures to native form.
- **Compacting VRAM allocator (DCA3):** evict least used, defragment with a move callback, report largest free block. The team still reports crashes after about an hour, attributed to fragmentation.
- **Disc reads by DMA with a streaming API (KallistiOS 2.2).** https://kos-docs.dreamcast.wiki/group__gdrom.html
- **8-bit world textures and streamed ADPCM music (Doom 64).**

### Skinned characters
- **DCA3:** two passes (positions, then normals), each looping over matrices; a fast path when a bone is near identity.
- **SH4ZAM `shz_xmtrx_blend()`** accumulates weighted joint matrices into one skin matrix [snippet].

### Real-hardware profiling and automation
- **SH-4 performance counters** with events for cache misses and for pipeline freeze by cause. https://kos-docs.dreamcast.wiki/group__perf__counters.html
- **KallistiOS 2.2 performance monitor:** scope probes counting two events per code block. https://kos-docs.dreamcast.wiki/group__perf__monitor.html
- **In-RAM sampling profiler (DCA3):** about 1,000 samples a second, about 5% overhead.
- **Emulator as a rule checker (DCA3):** every hardware mistake becomes an emulator assert; a native-CPU build runs under memory checkers.
- **Automatic console loop (Dream-TOS):** smart-plug power cycle, network loader upload, log file with a ready marker. https://raw.githubusercontent.com/richstokes/Dream-TOS/main/docs/TESTING.md

### Compiler and build
- **Size-optimised everywhere, speed-optimised hot files (DCA3):** within 1 fps of full speed-optimised, nearly 1 MB less code. https://sh4zam-com.elysianshadows.com/tips.html
- **Recommended by SH4ZAM:** fast math with the SH-4 sine and reciprocal-root instructions, link-time optimisation, `-fipa-pta`, `-DNDEBUG`. KallistiOS leaves these off by default.
- **Double-precision traps under single-precision mode:** unsuffixed float literals and float mixed with unsigned integers take a slow path.
- **Pinned toolchains:** the N64 ports pin one KallistiOS commit and one compiler version.

## Not verified
- Whether part of a "cache stall" figure is really store-queue waiting. The counters can separate the two.
- Throughput claims (SH4ZAM "4.5 million polygons a second", DMS-Engine "2.3 million") are self-reported.
