# What the old port gives the replatform: salvage inventory (lane eng-salv1, 2026-11-21)

Reading only. No build, no emulator, nothing in either program changed. Status: **finished, unaudited.**

- Old port: `origin/t15/int` at a5aca9cf9, read in a detached worktree. The engine line: `origin/engine` at 1b7d190f6.
- Line numbers are on t15/int. `src/` is the same on both branches except 3 files (`main.cpp`, `mes.cpp` and one more,
  +72 lines), so `src/` line numbers hold on `engine` too.
- Private data under `/root/re4data/private/`: listed and counted only. Folder names and counts appear here; no
  contents.
- "Inferred" marks every statement not read directly in a file. Sizes are lane rounds (one briefed lane to its
  hand-back, one to three hours), always as a range with a confidence.

## 1. For the owner

1. The engine already stands on the old port's data. Its bake reads the old port's converted PS2 files, and those
   exist for 106 rooms across all three discs, with PS2 character packages for 97 rooms and 114 PS2 cutscene movies.
   Chapter 1 does not need its assets converted again.
2. Parts the port's authors wrote for the Dreamcast carry over with adaptation: the disc read fixes, the AICA sound
   backend, the movie player, VMU saves, the controller-screen display, the crash screen, the warp and QA tools.
3. Sound is not "ours" as we thought. The music and sound-effect logic is Capcom's own sound driver from the original
   game. Only the layer that plays it on the Dreamcast's sound chip was written for the port. Carrying it over needs
   a technical ruling; it is cheap to run.
4. Nothing of the old drawing carries over except one skinning routine the engine already uses. This matches the plan.
5. The PS2 version plays many story scenes as movies, and the old port already plays them. That cuts the event work
   in chapter 1.
6. Hidden costs the plan does not list:
   - every room's bake also needs a recording of the old game running that room;
   - the inventory screens need 3 MB of memory the GameCube kept in extra memory the Dreamcast does not have;
   - 148 fixes live as switches inside the original code, and the engine builds that code with them off.
7. Effect on the plan: chapter 1 stays about the same size (22 to 36 lane rounds, low confidence). Much of it can start
   now, before the drawing redesign: sound, room loading, saves, movies, the script scheduler, and recording the rooms.
   What draws must wait for the new renderer. The rest of the game is smaller than it would be from scratch: 30 to 55
   lane rounds, low confidence.

## 2. Inventory

Classes:
- **REUSE**: as is. For original game code this means "hosted unchanged".
- **ADAPT**: lift and change; what must change is named.
- **NATIVE**: rewrite.
- **DROP**: not needed.
- **ALREADY**: the engine uses it or has its replacement.

Rounds are against `ENGINE_PLAN.md` section 7. "Saves" means fewer rounds than building it. "Costs" means work the plan
does not list.

### Row notes

**Row 13: Leon's handgun.**
- **How the original draws it.** The weapon is a `cObjWep` in the object table with its own model. Its matrices come
  from `MotionMove`/`matUpdate` under its parent, Leon's hand (`objWep.cpp:97-101`). It shows when `be_flag` bit 2 is
  set (`objWep.cpp:88-92`). The player keeps two display objects (`pl_wep.cpp:71-72`: `m_pWep`, `pObj2`).
- **How the old port draws it.** Like any model: `ModelTrans` reaches the native actor path, which converts the
  weapon BIN's display list once (`native_actor_fast.cpp:25`) and lights it with Leon's probe
  (`model_bridge.cpp:1412`). The models are PS2 ones from Test 24's data sets (private `wep26e`, `wep26g`).
- **What the engine needs:**
  1. the weapon model baked from `em/wep02.drs` (and later weapons) into the pack catalogue as a rigid model;
  2. the renderer walks the engine's cObj table for weapon objects with `be_flag & 2` and draws each with its model's
     part world matrices read in place (no copy);
  3. Leon's light record.
- **Present state.** `core/draw_e1.c:5` says the model is not in the pack. Seeing it only in the first picture fits a
  pack whose recorded first picture includes it (inferred, not checked). One round, medium confidence.

**Row 20: the sound driver needs a ruling.** `AGENTS.md` rule 4 lists the services that must be native. Sound is not in
that list, but the driver is original code that does work, not decisions. Two courses:
- **(a) Host `snd*.cpp` with row 21 under it.** Same music, sound effects and stream behaviour as the release. About
  0.28 ms at the cross on the console today (`SHELL_MAP.md:111`). It has its own random generator. 2 to 3 rounds.
- **(b) Write a native sequencer and voice manager.** 4 to 7 rounds, low confidence. Risk: music and effect timing
  drift that the outcome check does not see.

The lane recommends (a), recorded as a ruling in `HANDOVERS.md`. Script waits on streams must complete either way
(`audio_strm.cpp:5-12`: event code spins until a stream is ready).

**Row 24: route movies.**
- **What they are.** The PS2 presents many story events as prerecorded movies. The old port plays the PS2 movie while
  the original caller still runs every gameplay effect in source order (`ROUTE_CUTSCENES.md:4-9`).
- **Coverage.** 45 movies are in the Disc 1 tree (stage 1 and the start of stage 2). Each one is an event the engine
  does not have to draw in real time: no event bodies, camera tracks, lights or messages.
- **What is not known.** How many chapter 1 events have no movie (section 4, item 1).

**Rows 35 and 41: memory the plan does not list.**
- **The sub screen.** While the inventory, map, shop, files or radio screen is open, the GameCube moves 3 MiB of
  stage, module and room-heap bytes into ARAM (`sscrn_bridge.cpp:4-13`). The Dreamcast has no ARAM. The old port
  packs the bytes LZ4-compressed into the second TA bank and texture blocks (`subscreen_backing.cpp:1-20`, `SS_PACK`).
  That borrowing ties the screens to the old renderer's VRAM.
- **What the engine must decide.** Where those bytes go while a screen is open, or keep the room resident and give the
  screens their own region.
- **Code size.** Chapter 1's 29 room modules plus enemy modules are linked in the image (row 7). The proposed 1,024 KiB
  for hosted code (`SHELL_MAP.md:249`) was sized from E1's closure, not a chapter's.

**Row 50: the bake depends on the old port.**
- **What the engine pack builders read.** The old port's disc tree, plus a recording of the old game in the room:
  lights, environment, the nine logic streams, Leon's bind pose, and a RAM snapshot for HUD picture sizes
  (`native_pack.py:39-44`, `hud_fix.py:181-185`).
- **What that means.** Every room baked for the engine needs the old port to build and run that room in Flycast. The
  old port is frozen for changes, and it must stay buildable as a bake input through step 5.
- **Rooms not proven in the old port.** Castle 3-2, chapter 4 and the island were outside the published Test 27.2 discs
  (`KNOWN_ISSUES.md:97`), but they were run in lane builds (`CH-FIXES-CARRY.md` rows 26 and 31). The final-chapter rooms
  are not proven.
