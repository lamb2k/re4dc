# Build29 reviewed whole-source fallback sweep

Generated by `source_sweep29.py` from `source_catalog29.py` and the actual public Make recipe receipt. Physical `file:line` anchors name the source on this branch; compiler `#line` diagnostics may differ.

The coverage manifest reads **1,643 source files / 777,164 lines**, records **6,257 keyword/dispatch candidate lines**, and reviews **72 split groups**. This is a reproducible discovery/review boundary, not an assertion that every semantic branch or real-data trigger has been observed.

## Reading the table

`work fallback` performs alternative required work; `compile alternative` is selected by recipe and cannot be called a per-frame miss; `guard/drop/failure` has no successful slow image/audio result. Costs are **MODELLED structural work and traffic**, not console timings. B=payload bytes, V=vertices, W=matrices, N=visited records, K=keys, L=effective lights. A minimum `ceil(B/32)` line count assumes a contiguous aligned span; unaligned spans may touch another line, revisits can reload a line, and writes can allocate/evict lines. No D-cache miss rate is invented.

Recipe values below are the actual public-game command, including public missing-data overrides (for example `NMR_POOL_LOD=0`, whereas tracked CH2 requests 1). QA changes are listed separately. The full recipe receipt includes all queried feature families. These values do not certify private package admission.

The refreshed public recipe resolves `ACTOR_LIGHT_FAST_ONLY=1`. When this switch is 1, Build25 owns lighting, bypasses the old probe/exact dispatch and the Build29 bake adapter, and suppresses those scanner predictions. The queue's earlier barn exact-light counts belong to their original image recipe. Preserve that recipe when reproducing the observation; an explicit FAST_ONLY0 conversion comparison is a separate variant and is not an incremental gain claim over the current FAST_ONLY1 release.

Chapter reachability is source-level possibility unless the row explicitly cites the queue's existing barn console observation. The scanner and F29P/F29L live context are needed to assign light failures to actual Ganado, pitchfork, hay or barn prop parts. No model name or top offender is invented from unavailable game data.

Inherited Build26 individual reason references and units are preserved in `draw-reason-sites.tsv`; they complement the Build26 draw/model/world reports already in `docs/cloud/`. New FA29 bins are a bounded diagnostic subset; the table explicitly names uninstrumented paths.

Each Markdown group shows at most four representative source anchors. The complete resolved anchors are retained in [source-splits.tsv](../../../tools/d367/fallback_scan/receipts/source-splits.tsv), including every site omitted from this table.
