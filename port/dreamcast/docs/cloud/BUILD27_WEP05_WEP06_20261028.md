## Behavior retained

### Module registration and lifetime

Both real prologs register `WeaponInitFunc`, `WeaponMoveFunc = PlHandgunMove`
and their own object constructor. Their epilogs clear that object slot. The
existing [native module loader](../../game/platform/modules.cpp) and generator
rename/localize module symbols, retain each module's writable state span and
restore its pristine state on a fresh link. The shared handgun source is
compiled into each module through the existing per-module path; it is not
replaced with a process-global approximation. This matters for its own `pos`,
`tgt` and routine tables.

[Player weapon initialization](../../../../src/game/pl_wep.cpp) calls the
registered initializer after clearing the weapon motion table.
[The player's weapon routine](../../../../src/game/player.cpp) dispatches the
registered move function. The
[shared handgun implementation](../../../../src/wep/pl_handgun.cpp) retains
ready/aim, lock control, round consumption, hit checking, recoil, holster and
reload states. It uses the existing collision, inventory, camera and motion
services. None of those services is changed in this qualification.

### Civilian / wep05

The initializer creates object `0x2e`, attaches it to the player, installs
motions and loads effect archive slot `0x04` into muzzle-flash group `0x39`.
The object uses model/texture slots `0x06/0x05`, the right-hand parent at part
10, item id `0x29`, idle slot `0x34` and the retained spread parameters.

Firing starts weapon motion `0x32`, issues the original sound calls, sets the
shot-noise status bit and creates flash `0x39`. Motion completion returns the
weapon to mode/step 0. It has no cartridge-ejection path. Reload levels 0–2
select motion slots `0x33/0x35/0x36`, sound ids `0x16/0x20/0x21`, and refill
crossings at frames 75/48/28. The original `else if` means the first reload
entry starts animation and does not refill in that same invocation.

The motion map includes weapon footwork, damage and knife transitions,
while player-table slot `0x3d` comes from player archive slot `0x5d`.
The right hand is model 1; the left hand comes from weapon archive slot
`0x09`. All mappings remain the recovered source's mappings.

### Government / wep06

The initializer creates object `0x31`, installs the motion map and loads
muzzle-flash group `0x3a`. The base type uses model `0x06`, normal idle `0x34`
and item `0x2a`. Retained type 1 uses model `0x07`, idle `0x39` and item
`0x2b`; both use empty idle `0x3a` and texture slot `0x05`.

Firing selects `0x32` with rounds remaining or `0x35` on the last round,
preserves the sound/shot-noise/flash/vibration calls and ejects the cartridge.
Step 1 does not emit a second shot; the player routine owns the next state.
Cartridge creation uses model/texture slots `0x3f/0x40`, the original
right-hand transform, three random terms, gravity/lifetime and effect `0x13`.
Failure to allocate a cartridge does not dereference the missing object.

Reload levels 0–2 select loaded-magazine motions `0x36/0x3d/0x3e` or
empty-magazine motions `0x33/0x3b/0x3c`, sound ids `0x16/0x20/0x21`, and
refill crossings at frames 44/37/22. The crossing test is outside the setup
branch: unlike Civilian, it can fire during the first call when the motion
service reports a crossing. The fixture preserves and checks that distinction.

## SH4 compatibility audit

**Pointers and archive offsets.** The sources use the shared
[`RE4_MEM_LO/HI` bounds](../../../../include/types.h), already set to the
Dreamcast's P1 RAM interval in non-PowerPC builds. They use
[`PL_ARC_PTR`](../../../../include/global.h) through `WEP_ARC_PTR`; the existing
asset loader owns the native-endian archive-offset contract. No per-weapon
byte swapping or alternate archive layout is introduced. Real 32-bit pointer
casts and virtual dispatch are checked by native target compilation, not
inferred from the 64-bit host fixture.

**Routine state and ABI.** The modules address named fields and individual
routine bytes. There is no hard-coded vptr displacement or new endian-sensitive
packed routine-word store. The shared handgun `MotionMoveI` alias targets the
existing main-image `MotionMove` entry, as other already-supported weapons do;
it is not an alias to an inaccessible file-static function. The existing
shared-source alignment directive is retained; this build adds no assembly
or linker mechanism.

**Sparse pools.** Neither module nor their shared handgun routine directly
walks `EmMgr.pArray` or multiplies `EmMgr.size`. Object creation uses the
existing `ObjMgr.createBack`; cartridge creation uses `SetObj10`. The ordinary
native module route is therefore eligible for the manually audited
`ENEMY_DEMAND` module allowlist.

**Placement-new lint qualification.** The existing
[assetpipe lint](../../tools/assetpipe/wiring.py) flags `new (obj)
cObjCivilian()` and `new (obj) cObjGovernment()` because its generic rule also
catches the known enemy pre-initialization trap. These two sites are safe:
[`cManager<cObj>::createBack`](../../../../include/cManager.h) clears the
storage before constructing it; [`cObjMgr::construct`](../../../../src/game/obj.cpp)
assigns the serial/id after `ObjInitFunc`; list insertion follows construction.
There is no previously written enemy `subArc` or sparse-slot metadata for
value initialization to erase. Existing native weapon classes use the same
construction convention. Changing these calls solely to silence the broad
lint would not repair a demonstrated defect, so they remain unchanged.

**Existing domain assumptions.** Reload level is an item tuning level in
0–2. Model/texture/motion/effect slots must exist in the selected private
weapon archive. The real initializers retain their existing allocation/model
failure behavior. This work does not claim arbitrary corrupted archives,
invalid tuning bytes or failed model initialization become playable. Clean
refusal of a missing module is separately implemented at equip admission,
before invoking an unavailable constructor.

## Focused validation

[wep0506_host.py](../../tools/cloud/build27/wep0506_host.py) compiles the complete
three module/object source files against the shared synthetic service boundary
in `weapon_fixture_prefix.hpp`. It does not copy the gameplay algorithm into
an expected-output implementation. Call recording controls model/motion,
sound, effect, object allocation, random and cartridge services. Synthetic
archives provide distinct slot identities; no private data is present.

**All 38 cases pass at `-O2`, and all 38 pass with AddressSanitizer and
UndefinedBehaviorSanitizer.** Both final compiles have no warnings. The
[normal receipt](../../tools/cloud/build27/receipts/wep0506-host.json) and
[sanitized receipt](../../tools/cloud/build27/receipts/wep0506-host-sanitized.json)
cover real registration/placement callbacks, allocation boundaries, both
Government model types, all 26 motion mappings with unrelated slots untouched,
first/last shot and repeat-step suppression, all reload levels with loaded and
empty variants, cartridge transforms/random-call order and cartridge refusal.

The host-only adaptation widens pointer carriers and the pointer-validity
interval, and replaces the two effect-owner `(int) this` casts with
`intptr_t` in generated copies. It cannot prove SH4 class layout or target
pointer validity. `PlHandgunMove` is a registration target in this fixture;
its complete unchanged production unit is covered by the real module build.
The receipt records all original source hashes, these exact adaptations,
the compiler command, baseline source-byte equality and the manually reviewed
lint findings. Host callback tests, actual SH4 compilation and local
equip/fire gameplay acceptance are distinct gates.

### Equip admission and recovery fixture

[equip_contract.py](../../tools/cloud/build27/equip_contract.py) separately
executes the current production module lookups, `wep27_read_file`, availability
and refusal/recovery helpers, `InitModule`, `ReleaseWepData`, `ReadWepData`,
item `weaponId`/`arm`/`debugWeapon`, player `weaponLoad`, and the affected
subscreen/debug-option caller fragments. The weapon, archive and file-name
tables are extracted directly from current production source. The selector
oracle is the original base's selector body; it is not an independently
rewritten mapping.

All four `WEAPON_HEAP4` × `WEAPON_ARCHIVE_REUSE` compositions pass at `-O2`
and under ASan/UBSan: **1,960 selector/bounds comparisons per composition**,
plus **34 flow cases with HEAP4 off / 35 with HEAP4 on**. The total is 7,840
selector comparisons and 138 flow cases per normal/sanitized run. The
[normal equip receipt](../../tools/cloud/build27/receipts/equip-contract.json)
and [sanitized equip receipt](../../tools/cloud/build27/receipts/equip-contract-sanitized.json)
include current source hashes, the original-base identifier, extracted-body
hashes and exact compiler commands.

Coverage includes rejection before inventory mutation or I/O; all three newly
admitted weapons; malformed/short module names; unknown descriptor ids;
native `OSLink` refusal; successful and refused heap ownership; restoration of
an owned, available previous weapon; genuine bare-hand recovery; and explicit
no-weapon state when neither previous weapon nor bare hands are available.
No rejected descriptor executes a prolog or the halting `DLL_Link` wrapper.
The debug-option regression executes its actual caller fragment: a late bind
refusal restores the prior weapon, and the guarded trailing `debugWeapon`
call cannot republish the failed selection. Both subscreen sites preserve the
restored bullet-type value. Thompson is weapon number **12 decimal (`0x0c`)**,
item `0x34`, DLL file `0x72`, module 56; the distinct Red9 variant maps
weapon 3/type 2 to archive index `0x12` and DLL file `0x0a`.

The synthetic module roster uses real metadata ids but is deliberately small;
the actual image roster is validated by the target gate. DVD, native linking,
module callbacks, allocation, item metadata and resource retirement are
recorded service boundaries. Low-address `MAP_32BIT` archives preserve the
original 32-bit pointer arithmetic; the fixture's permissive host compiler
warnings at those casts do not constitute target ABI evidence. It executes
no private assets, audio, PVR work or full gameplay loop. No claim is made
that every existing fatal asset/overlay-file read failure has become a clean
equip refusal.

## Native size and bounded cost

The [generated module build receipt](../../tools/cloud/build27/receipts/module-build.json)
prices each complete relocatable native module, including its own copy of
the shared handgun code. These production modules use the existing `-O1`
recipe; the host fixture's `-O2` is a separate control. Sizes precede final
image linking/section collection and are not an image-delta claim.

| Module | Executable bytes | Read-only data | Writable data | BSS | Total allocated | Largest compiler local stack frame |
|---|---:|---:|---:|---:|---:|---|
| wep05 | 6,400 | 544 | 0 | 24 | 6,968 | 92 B, shared handgun fire step 0 |
| wep06 | 6,888 | 544 | 0 | 24 | 7,456 | 96 B, cartridge creation |

Each has zero pristine writable-data-copy bytes. Existing generator checks
for constructors, common symbols and exported entries pass. The 82/85
external imports introduce no names beyond the baseline wep02 plus wep11
import union. A local stack frame is not a complete game call-chain watermark;
model, sound, collision and other callees have their own stack and work.

The [entry-cost receipt](../../tools/cloud/build27/receipts/entry-cost.json)
executes actual SH4 registration prefixes and complete epilogs. The prolog
window stops at the `OSReport` call: logging and its return tail are excluded.
It verifies the actual init/move/constructor pointers, correct object slot and
untouched adjacent state.

| Measured window | Warm cycles | Cold-I cycles | Loads | Stores | Distinct 32-byte data lines | Observed stack |
|---|---:|---:|---:|---:|---:|---:|
| wep05 registration prefix | 20 | 52 | 8 | 4 | 5 | 4 B |
| wep06 registration prefix | 20 | 51 | 8 | 4 | 5 | 4 B |
| wep05 epilog | 4 | 26 | 1 | 1 | 2 | 0 B |
| wep06 epilog | 4 | 26 | 1 | 1 | 2 | 0 B |

**MODELLED whole-frame contribution:** for a hypothetical frame containing
one measured epilog and one registration prefix of the same module, the
included work sums to 24 warm cycles: **0.000120 ms at 200 MHz**. Summing the
independently cold-I windows gives 78 cycles / 0.000390 ms for wep05 or 77
cycles / 0.000385 ms for wep06. This is a bounded callback contribution, not
the cost of equipping, loading a model, firing, reloading or an entire frame.
It omits logging, loader/state restoration, allocation, storage, texture,
sound and game services; independent cold windows are not a continuous-frame
cache simulation. These modules add no unconditional per-frame worker, but
their resident bytes and cache effects are not priced as zero. Actual weapon
equip/fire behavior and whole-frame cost remain local acceptance work.
