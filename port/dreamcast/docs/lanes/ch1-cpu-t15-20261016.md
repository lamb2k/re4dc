## Skipped-tick accounting audit

The main loop renders the previous prepared image, advances game logic, then calls
`re4dc_pace_decide_image()` before `Trans()` prepares the next image
(`src/game/main.cpp`). The current-presentation flag `re4dc_pace_skipping` and
next-image flag `re4dc_pace_drop_models` are different. A skipped presentation
iteration can therefore prepare the next visible image. Charging all of its
non-TaskScheduler time as removable work would count useful work as waste.

The existing recipe already uses `PACE_CATCHUP=2` and `PACE_TRANS_SKIP=4063`.
`Trans()` avoids model preparation when that next image is dropped. Effect bit
2048 deliberately preserves state-carrying callbacks in logic-only mode. Sound,
UI movement, fades and other stateful callbacks cannot simply be dropped without
the required STRICT/gameplay checks. The reported 6.4 ms is an accounting target,
not an established saving.

Further accounting must distinguish current draw/skip from next prepare/drop,
report non-overlapping function self costs for OTHER, and separate useful work,
waits, and redundant presentation work. No logic or pacing behavior was changed
by this audit.

checkpoints, not against this room-entry value.

`cxt16skiprW` changes only the pacing diagnostic to `PACE_MODE=fast PACE_FORCE=2`.
It alternates eligible image drops. Sampling frames 500:799 at stride 7 includes
both parities. Its `_end` is `8c429098` (-288 bytes versus the baseline); this is a
diagnostic binary difference, not an optimization. `PACE_FORCE` also runs
iTaskScheduler every iteration, whereas the production skip policy normally
omits it on skipped presentations. Account that cost separately before comparing
with production console observations.

The trace boundary is `Frame_cnt++`, after rendering and clearing the preceding
OT. A trace therefore covers logic/preparation N and rendering N in the next
loop iteration. Call groups named world-draw-present/absent describe that trace
window; they are not physical drawn/skip iteration labels. A draw-plus-drop pair
can be analyzed without charging the next visible image's preparation as waste.

`FilterTrans` is deliberately not masked by 4063 (bit 32 is clear). Its callees
include state changes: Filter08Trans eases the scope ratio and consumes jitter,
and Filter06Trans advances rain particles. Blanket omission is not an exact
presentation optimization. Likewise Render_done includes scenario task wake/wait
behavior as well as GX bookkeeping; its name does not establish removability.

The host trace helper now supports `ACTORPLAN_KEEP_TRACES=1` or `trace/keep.txt`
for the follow-up ownership replay. This changes no runtime code. The explicit
`BENCH_WORLD_BATCH` fixture hook and bounded converter are carried forward for
the pending spatial32v3 comparison; neither changes the default asset ladder.
The batched static geometry is requantized (maximum measured position error
1.552 mm, UV error 0.000071); protected dynamic and gated parts remain exact.
Visual and gameplay gates are required before adoption.
